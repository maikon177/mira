# Notificações decisivas

## Objetivo

Criar notificações que não sejam apenas lembretes comuns.

A notificação deve exigir uma decisão rápida do usuário.

## Notificação ruim

```text
Fazer orçamento.
```

Problema:

- vaga;
- fácil de ignorar;
- não mostra motivo;
- não oferece ação.

## Notificação ideal

```text
Agora: responder orçamento do João.
Leva 10 minutos e pode virar venda.
Ações: iniciar / adiar / dividir / cancelar.
```

## Botões recomendados

- Iniciar;
- Concluir;
- Adiar 15 minutos;
- Adiar 1 hora;
- Dividir;
- Cancelar;
- Justificar.

## Tipos de notificação

### 1. Simples

Para tarefas comuns.

### 2. Decisiva

Para tarefas importantes.

### 3. Insistente

Para tarefas com prazo ou cliente.

### 4. Revisão

Para tarefas ignoradas ou adiadas várias vezes.

### 5. Próxima ação

Mostra apenas o primeiro passo.

### 6. Risco

Mostra impacto de não fazer.

Exemplo:

```text
A impressora parada pode atrasar as entregas de hoje. Primeiro passo: verificar o bico.
```

## Regras de notificação

- Não mandar notificação infinita.
- Não transformar tudo em urgente.
- Não usar tom agressivo.
- Sempre permitir adiar ou cancelar.
- Registrar a resposta do usuário.
- Se ignorar várias vezes, mudar abordagem.

## Estratégias de abordagem

### Direta

```text
Agora faça: responder João.
```

### Motivo financeiro

```text
Responder João agora pode virar venda. Leva 10 minutos.
```

### Passo pequeno

```text
Primeiro passo: abrir a conversa do João e ler o pedido.
```

### Urgência

```text
Essa tarefa está atrasando a entrega de hoje.
```

### Anti-procrastinação

```text
Faça só 5 minutos. Depois você decide se continua.
```

## Métricas

Cada notificação deve registrar:

- enviada;
- aberta;
- ignorada;
- iniciada;
- concluída;
- adiada;
- cancelada;
- dividida.

Essas métricas alimentam o laboratório de abordagens.
